# Spine Pair Review — WORLDBOUND: NOMAD

## Overall verdict
The pair is a solid downstream contract. Every UJ and FR from the PRD and addendum maps to a surface, a component row and a flow. All flow numbers reconcile with the addendum tables: UJ-1 ends with 16 days used and €423, UJ-2 at €20, Day 11 and 17 days used, Flow 5 at Day 6 → Rome Day 7 with €1,140. Every `{token}` reference resolves, and the stated contrast values match recomputation. Two high gaps would push guesswork onto story-dev. First, several components that are "navy" in light mode collapse in dark mode because they bind to `primary`/`ink`, which flip to ochre and cream (1.0:1 collisions). Second, the Call home sheet has no defined trigger point and no persistent entry after "Not now". Fix those two and the medium state gaps, and the pair is ready for architecture and stories.

## 1. Flow coverage — strong
Checked: UJ-1, UJ-2 and UJ-3 from PRD §2.4, plus FR-1 to FR-23, against Key Flows and IA. Each UJ has a named protagonist, numbered steps, a bold climax and failure paths. The UJ-1 edge cases, the UJ-2 Day-25 edge case and the UJ-3 exhaustion and zero-day cases are all present. EXT FR-18/FR-20 are covered by Flow 4 and FR-17/FR-23 by Flow 5. FR-19 is covered through the region inset, the stamp codes and Content Assets. All euro and day arithmetic was recomputed against addendum §2, §3, §4 and §5 and matches. That includes budget/comfort €56/€104, the night train at +0 days, and €240 + €96 = €336.
### Findings
- None blocking. (One string mismatch in the UJ-3 failure path is logged under §7.)

## 2. Token completeness — adequate
Checked: all 35 colour roles have a light hex and a `-dark` hex (70 values). Every `{colors|typography|rounded|spacing.*}` reference in DESIGN.md prose, component frontmatter and EXPERIENCE.md resolves. The contrast table was recomputed and every listed value matches within 0.05 (e.g. pin/background 4.68, on-unavailable 5.20, Nomad rows 4.84).
### Findings
- **high** Dark-mode collisions, caused by "navy" components bound to role tokens that flip in dark mode. `button-primary.icon` = `ochre-light` on `primary-dark` (#E0A243 on #E0A243, 1.0:1). `map-marker-home` icon `on-navy-dark` on fill `ink-dark` (#F4EFE1 on #F4EFE1, 1.0:1). `region-loupe.zoom-tag` (`primary` pill + `ochre-light` icon). Tabs selected (ochre icon on `primary` fill). Intro goal box (`primary` fill + ochre caps caption + cream goal sentence; cream on #E0A243 = 1.9:1). Feedback box correct ("navy fill, ochre check"). None of these pairs appear in the contrast table (DESIGN.md frontmatter `components`; Components table rows Buttons, Tabs, Intro, Feedback box; Region loupe → Zoom tag). *Fix:* decide per component whether it is "brand navy in both modes" (bind to a mode-stable token such as `cover-explorer`/`on-cover-explorer`) or "primary role" (add `on-primary-icon` with a dark value such as `#0A1826`). Give `map-marker-home` an icon token that contrasts in dark mode. Add these pairs to the contrast table.
- **medium** Component specs carry many type sizes with no typography token: 12.5 px (consequence line, warning line, tip), 13.5 px 600 (destination chip, info banner, mode card meta), 14 px 600 (sight name), serif 14 / 14.5 / 19 / 24 px (polaroid title, stamp-page name, running-total sum, confirm title, passport-screen count), 16 px bold/600 (mode card, menu row) and 11.5 px (passport-screen goal line). Downstream code will invent ad-hoc tokens (DESIGN.md → Components table). *Fix:* map each to an existing role (e.g. confirm title → `question`/`tagline`) or add a few roles (`meta` 12.5, `label-strong` 13.5/600, `serif-sm` 14/600), and reference them by name.
- **low** Literal values left in component frontmatter and shape prose: `answer-row.min-height: 52px`, `progress-dot.size: 28px`, cover radii `8px 16px 16px 8px` / `3px 8px 8px 3px`, menu row 60 px (DESIGN.md frontmatter; Shapes). *Fix:* add spacing/rounded tokens or accept them as one-off literals explicitly.

## 4. State coverage — adequate

## Mechanical notes
- EXPERIENCE.md frontmatter uses `title:`. The shape examples use `name:`. Consider adding `name: 'WORLDBOUND: NOMAD'` for parity with DESIGN.md.
- `scrim` / `scrim-dark` are 8-digit hex (`#0A182661`, `#00000080`). The spec says "hex strings", so confirm downstream token tooling accepts alpha hex, or split the value into colour plus opacity.
- `typography.*.note` fields (`tabular-nums`, `uppercase`) carry load-bearing rendering rules outside the standard keys. Make sure the token export keeps `note`, or promote them to `fontFeature` / `textTransform`.
- UJ-1 step 3 says "the loupe shows Europe" at Bergen, but the region list (Europe incl. Madrid, NA/Atlantic, East Asia/Pacific, Oceania) never says which region Bergen belongs to. Add "Europe (incl. Bergen, Madrid [EXT])".
- No Mermaid in either spine. All internal links (`DESIGN.md` ↔ `EXPERIENCE.md`, `imports/…pptx`) resolve. The `mockups/*.html` links resolve once promotion runs (known pending).
- Both files are `status: draft` with `updated: 2026-10-13`. That is consistent.

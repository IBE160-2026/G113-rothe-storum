- (decision) Paradigm: functional core, imperative shell. Pure TypeScript rules engine (state + action -> new state or rule error) and pure queries; React UI as thin shell. Alternatives weighed: vanilla TS + DOM (fewer deps but hand-rolled focus traps, sheets, re-render; more code for AI to get wrong), Svelte/Preact (fine but less common in course examples). React chosen for ubiquity and Claude Code familiarity; rules layer stays framework-free so the choice is reversible.
- (decision) Stack: Vite 8 + React 19 + TypeScript, Vitest 5 for unit/integration, Testing Library for components, Playwright for e2e at 375 px, ESLint + typescript-eslint + Prettier, zod for content validation. Static SPA, no backend, no server state.

- (decision) State: single GameState owned by src/rules; UI holds it via one useReducer-style store wrapping the rules apply(); no state library. Draft UI state stays in components (EXPERIENCE State Model).
- (decision) Money and days are integers (whole euros, whole days). Accommodation price computed only in rules/money.ts with round-half-up (Decision E).
- (decision) Content lives as JSON in /content, validated by zod schemas at load and in a test; rules receive content as an argument (never import it), so tests use small fixtures (NFR-7).
- (decision) Errors: rule violations are returned values ({ok:false, reason}) not exceptions; reason codes are a closed union used both for unavailable-with-reason UI and tests.
- (decision) Testing: every FR consequence in SM-1 gets a test named with its FR id; UJ-1 and UJ-2 as scripted rules tests; SM-3 balance test over real content; Playwright e2e for UJ-1 and UJ-2 on 375 px viewport; content validation test. CI-free: npm test / npm run test:e2e documented in README.
- (decision) Persistence: core uses a storage adapter (try/catch, works without storage) for intro flag + last name only. EXT save serialises GameState with schemaVersion; unreadable save discarded (FR-20).
- (decision) Copy: all player-facing strings as templates in src/ui/copy.ts mirroring EXPERIENCE Copy templates; components never hard-code strings.
